# AGENTS.md

Repository guidance for coding agents working on `webhid-wheel`.

## What this repo is

`webhid-wheel` is a zero-runtime-dependency ESM package for reading USB HID
steering wheels over WebHID, plus optional Web Components and a demo page.

Two public entries:

- `webhid-wheel` — DOM-free core: `WheelManager`, `WebHIDWheel`,
  `WebHIDDevice`, `mapChannels`, calibration, setup profiles.
- `webhid-wheel/ui` — registers the custom elements. Importing this entry has a
  side effect and must not be tree-shaken.

The demo in `index.html` and `script.js` consumes the package entries from
`dist/`.

## Read first

1. `readme.md` — public overview and examples.
2. `docs/component-integration.md` — canonical integration contract for humans
   and agents.
3. `docs/lapster-integration-plan.md` — current architecture, profile schema,
   accepted decisions and migration status.
4. `docs/device-config-and-rigs.md` — device/mapping data model.
5. The code in `src/core/` and `src/ui/` before changing behavior.

## Commands

```sh
npm run build       # copy/validate src -> dist
npm test            # Node test suite
npm run test:ui     # Playwright component tests
node test/server.mjs # local demo server used by Playwright
```

On this Linux workstation Playwright may need:

```sh
LD_LIBRARY_PATH=/tmp/pwlibs/root/usr/lib/x86_64-linux-gnu npx playwright test
```

Package smoke test:

```sh
rm -rf /tmp/wheelpkgtest && mkdir -p /tmp/wheelpkgtest
npm pack --pack-destination /tmp/wheelpkgtest
# install the tarball in a temp project and import both entries
```

Do not add runtime dependencies without an explicit reason. `@playwright/test`
is a devDependency only.

## Layout

```text
src/core/          DOM-free library implementation
src/ui/            custom elements, Shadow DOM, storage adapter
dist/              generated by npm run build; do not hand-edit
test/*.test.js     Node tests
test/ui.spec.js    Playwright component tests
index.html         demo shell
script.js          demo boot and app-level wiring
docs/              architecture, integration and hardware notes
```

`webhid-wheel.js` and `webhid-wheel.d.ts` are compatibility shims. Keep them
re-exporting the core entry.

## Non-negotiable invariants

- Core must import and construct in Node without `document`, `navigator.hid`,
  `localStorage`, `requestAnimationFrame` or DOM access.
- `WheelManager` construction stays DOM-free. `WebHIDWheel` may check
  `navigator.hid`.
- `webhid-wheel/ui` registration must be guarded with `customElements`, and the
  UI entry must remain in `sideEffects`.
- `requestDevice()` and a user-gesture `manager.connect()` belong in click or
  key handlers. Reconnection uses `getDevices()` only and never prompts.
- Setup profiles use schema v2: multi-device aliases, required VID/PID,
  normalized `0..1` settings, app-owned `metadata`, v1 migration.
- Do not drop unknown profile metadata.
- Every UI element uses Shadow DOM. Do not add global selectors, global key
  handlers or pointer capture outside the component.
- Do not render on every HID report or write storage on the input path.
- Keep protocol FFB profiles (`registerProfile`) separate from setup profiles.
- Do not add vendor FFB protocols without a hardware note and tests.

## Change workflow

- For behavior changes, add or update tests first or in the same change.
- Keep API changes in `src/ui/index.d.ts`, `src/core/index.d.ts` and
  `webhid-wheel.d.ts` consistent.
- Update `docs/component-integration.md` for any consumer-visible API, event,
  slot, storage or behavior change.
- Update `readme.md` when install, entry points or headline behavior changes.
- Update the status/version in `docs/lapster-integration-plan.md` when the
  package revision changes.
- Run `npm run build`, `npm test` and `npm run test:ui` before handing work back.
- Check `git diff --check` and `git status` before committing.

## Versioning and docs

- Current package version is in `package.json` and mirrored in the Lapster plan.
- Use `npm version <x.y.z> --no-git-tag-version` for a manual bump unless a tag
  is explicitly requested.
- Do not hand-edit `dist/`; run the build.
- Documentation is part of the deliverable, not an afterthought. A stale event
  table or missing integration guide is a defect.

## Branch and dev preview

- Feature work happens on `feature/core-ui-package`.
- `main` on the source repo is kept stable; do not merge or rewrite it unless
  asked.
- The dev preview deployment shell is
  `joegaffey/webhid-wheel-dev`. It deploys by ref:

  ```sh
  gh workflow run pages.yml --ref main -R joegaffey/webhid-wheel-dev \
    -f ref=feature/core-ui-package
  ```

- Dev URL: https://joegaffey.com/webhid-wheel-dev/
- Verify deployment with `/version.txt` and a cache-busting query.
- Do not commit, push or deploy unless the user asks. When asked to deploy,
  push the source branch first, then run the workflow and watch it.

## Consumer handoff

When another app or agent is integrating the package, point them at
`docs/component-integration.md` and use its agent checklist. Do not invent a
second integration path in ad-hoc notes.
